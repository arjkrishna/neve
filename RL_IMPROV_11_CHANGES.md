# RL Improv 11 — Changes Reference

All changes and findings **after** the state at the end of
`RL_IMPROV_10_CHANGES.md`, which closed at the **`rcca_awac_v3`** run and
the **pid19116 sweep** (§14–16): AWAC + step-PER + warm-start + entropy-floor
`log_std_min=-2`, reaching **~86 % strict on the single restore-state
pid19116** but only **~35 % mixed** across the 5 fork-restore states, with a
characterized log-std / rail collapse by ~250 k steps.

**This document covers everything after that 86 % milestone:**

1. **Plan v11 Stage 1 — the offline-RL bake-off** (AWAC / IQL / BC-AWAC /
   CQL / KL-anchor, offline on the saved V2+V3 buffers). *Dead end* — every
   variant landed at-or-below the 0.537 warm-start anchor. Diagnosis: the
   buffer was generated by a narrow heuristic, so offline RL on it cannot
   exceed the warm-start ceiling.
2. **Plan v12 — the pivot to a from-z=345, multi-target random-heatup
   harvester + per-daughter online AWAC** (no offline, no heuristic seed).
   The multi-target trick, the rolling-save harvest infra, and the LCCA
   Challenge-1 run.
3. **`lcca_awac_v1`** — the first from-z=345 LCCA AWAC run: healthy start,
   then a *soft* collapse (bounded by the `-2` floor) to a ~7 % eval plateau.
4. **The 6-cluster forensic** that overturned the working diagnosis: the
   stability bug is a **log-std CEILING explosion** (not the dormant-alpha /
   floor theory), and the **LVA-confusion is structural** (present when
   entropy was healthy), a missing "hook" at the bif2 fork.
5. **`lcca_awac_v2` — EXP-1 (`log_std_max` cap) + EXP-2 (`balanced_fraction`
   0.6).** EXP-1 fixed stability decisively; EXP-2's effect on the metric
   that counts (deterministic eval) is unproven — a host interruption killed
   the run at 470 k with only one early eval.

**Standing constraint (unchanged from RL_IMPROV_10):** per iteration change
ONLY the variable under study + stabilization knobs; never touch
reward / observation / terminal / dynamics unless explicitly asked. Every
code change below is a stabilization knob (entropy bounds) or a data-mix knob
(sampling fraction); no reward/obs/terminal/dynamics change was made.

### Idea

Warm-start from `checkpoint250531.everl` and run **offline** RL on the two

- **1C — BC-pretrain then AWAC continuation.**

### Result — the dead end

**All four offline variants landed at-or-below the 0.537 warm-start anchor**
on the canonical 54-seed eval. Forensic of `saved/replay_buffer.npz` +
`saved/rcca_heuristic_cache.npz` showed **why**: the demo (heuristic) slice
is narrow — 68 % of `gw_trans` mass on three discrete values
(`PHASE_A_GW_TRANS=10`, `PHASE_B_GW_TRANS=1.5`, `daughter_gw_trans=2.0`),
`cath_rot` std = 0 (hardcoded zero), `cath_trans` rigidly = 0.8·`gw_trans`
(`CATH_FOLLOW_RATIO`). The V3 buffer was 0 % `is_demo` (aged out / persistence
bug) — effectively 100 % explore, but incoherent flailing, not skilled
recovery. **Offline RL on a forward-uniform, retraction-free buffer cannot
exceed the warm-start ceiling.** Stage 1 deprecated; the rest of Plan v11
(the online stabilization stack) is reused inside Plan v12.

## 4. Plan v12 — the pivot: from-z=345 multi-target heatup + per-daughter AWAC

The lesson from §2: to beat the ceiling we need **diverse data with a true
success signal that is NOT heuristic-narrow.** Random heatup provides it. Plan
v12 mirrors the v3 pipeline shape (seed buffer → online AWAC) but replaces the
narrow heuristic seed with a **random multi-target heatup harvested from
z=345**, then trains **independent per-daughter online AWAC runs**. **No
offline RL, no BC pretrain, no heuristic seed anywhere.**

### 4a. The multi-target trick (4-virtual-envs-per-SOFA)

A single SOFA tick advances the physics once; Reward / Terminal / Pathfinder /
ArcLengthProgress / Target2D each attach to that state but grade against a
**target coordinate**. Instantiating **4 independent per-target quadruples**
(RCCA/LCCA/RVA/LVA) grades the same tip trajectory against 4 goals at once →
one SOFA episode yields up to 4 per-target RL Episodes. Yield ≈ 2.5–3×
supervisory tuples per tick (2× in the shared trunk, **4× at the fork-commit
step** — where exactly one virtual env sees the latched `+1` and the other
three see `-0.05` "wrong-daughter" supervision, the hard-to-get negative
signal). Fork-reward bookkeeping (Plan v9 `+1` latched / `-0.05` re-firing)
runs **independently per virtual env** against its own planned path.

### 4b. Rolling-save harvest infra (committed in `662d5d4`)

- Worker-side **rolling flush every N SOFA episodes** (memory-safe: clear
  after flush), chunk files partitioned per daughter, two versions: **A** =
  partition by `target_branch_idx`; **B** = partition by
  `final_branch_short == target` ("wire ended in that daughter").
- `--heatup_only` + `--heatup_save_every` + SIGTERM clean-flush; the
  `EPISODE_OUTCOME` log line (env5) carries everything needed to filter the
  npz later (`final_branch`, `reason`, `is_clean`, `grader_success`,
  `received_correct/wrong`, `return`, `steps`, `pid`).
- `EVE_RL_EVAL_HARD_TIMEOUT_MIN` raised to a year so the harvest can run for
  days (`launch_rcca_z345_multitarget_heatup.sh`, container `heatup_z345_v1`).

The indefinite harvest ran and produced the per-daughter heatup data that
seeds the per-daughter AWAC runs.

### 4c. `is_clean` — the latch-safe (R17-safe) definition

`is_clean = (final_branch_short == target_branch_short) AND
final_branch not in (unknown, other) AND received_correct_daughter AND NOT
grader_failure_timeout`. This is read from the terminal `info`, **NOT** the
`_reached_target_daughter` latch (which sets True the first step the wire
touches the target and never resets — that would mark a drifted-off failure
as clean and poison the balanced sampler). Verified downstream: the LCCA
seed's clean lane is **100 % LCCA** (§7d).

## 6. `lcca_awac_v1` — the run (soft collapse to a ~7 % plateau)

`launch_lcca_awac_v1.sh`: `--env_version 5 --insertion_z 345 --replay_mode
step --per --algo awac --balanced_fraction 0.3 --grad_clip 1.0 --hidden
256 256 --embedder_layers 0 --learning_rate 3e-4 --log_std_min -2
--update_per_explore_step 0.5 --replay_buffer_size 11e6 --heatup_cache_file
lcca_awac_seed_v1.npz --pretrain_updates 10000 --target_branches "…LCCA.mrk"`.
(11 M buffer so the 1.07 M seed is <10 % of capacity → the clean lane is not
FIFO-evicted early.)

**Anti-rail setup carried in** (from Plan v10/v11 work, in
[eve_rl/eve_rl/algo/sac.py](eve_rl/eve_rl/algo/sac.py)): the AWAC policy loss
re-enables SAC's **auto-tuned entropy** (`_update_alpha` no longer stubbed to
zero for AWAC), plus optional per-dim entropy bonus + mean-margin penalty
(`--entropy_beta_per_dim`, `--action_mean_penalty`, default off), and
`log_std_min` default flipped `-20 → -2`.

### Run trajectory

- **Healthy pretrain + handoff:** entropy_proxy flat at **+2.7**, clamp
  ~0.4 %, `alpha` auto-relaxed to 0 (entropy already far above the −4 target),
  q1_mean bounded, 0 NaN — clean through the pretrain→explore handoff and the
  first 50 k online steps (where v10/v11 had already collapsed).
- **Then a slow slide:** entropy +2.7 → +0.8 (accuracy still rising) →
  **negative by ~382 k** → −2.7 @ ~900 k; clamp climbed 0.4 % → **~25 %**.
- **Eval Quality: `10.2 → 3.1 → 7.1 → 7.1 %`** (@260k / 507k / 752k / 1009k).
  A **soft** collapse: bounded by the `log_std_min=-2` floor (std capped
  ~0.135) into a **3–10 % oscillating band** — unlike v10/v11's *hard*
  collapse (`log_std_min=-20` → entropy −12, ~0 %). The floor bounds the
  damage but the policy is **stuck**, not learning.

The initial (pre-forensic) diagnosis was "auto-entropy dormant at
`target_entropy=-4`; raise it to ~+1.0". **The forensic (§7) overturned
this.**

## 7. The 6-cluster forensic (workflow: `lcca-lva-investigation`)

A 6-agent parallel investigation over v1's 869 MB of logs + policy snapshots +
seed npz (10,944 episodes), then a synthesis. The decisive results:

### 7a. LVA-confusion is STRUCTURAL, not the collapse

Outcome taxonomy (10,944 episodes): **trunk/vessel_end 42.6 %, LVA/
wrong_branch_timeout 38.3 %, LCCA/success 6.9 %.** LVA was already **37.4 %
in the earliest phase** (entropy healthy at +2.66, eval 10.2 %) and stayed
flat ~38 % through the entire collapse. LCCA-success was stuck 5–8 % **with no
upward trend from step zero.** → The policy never learned the correct
daughter; **an entropy/stability fix alone cannot fix LVA.** Among the 5,075
episodes committing to a left-side daughter, LVA won **83.5 %** (≈5:1 over
LCCA).

### 7b. The mechanism — a missing leftward "hook" at the bif2 fork

At the bif2 fork (world-CS z≈400; ostium z≈430), entering LCCA needs the tip
deflected from x≈73 → x≈50. **Successes execute this 100 %** of the time
(mean min tip-x 49.7 in z∈[395,408]); **LVA failures 6 %** (mean min tip-x
70.1) and instead travel straight up (tip-x ~75–79) into corridor
`Centerline curve (18)` → LVA. **F0:F2 = 6:94** (94 % never genuinely reach
the LCCA ostium). Dwell: LVA failures spend ~47 steps in corridor (18) and
~7 working the ostium; successes invert that (~48 in LCCA). *(LVA
`wire_fold_stall`, n=47, is the opposite — ~66 % F0, wires that reached LCCA
then folded; partly a grader-label artifact.)*

### 7c. trunk/vessel_end (43 %) = under-reach + buckle (NOT over-insertion)

These wires insert **~66 mm LESS** than successes, stall ~28 mm **short** of
the ostium (peak z~402), then **coil/slide back ~35 mm while insertion keeps
growing (+45 mm)** — **96 %** show the buckle signature. They never traverse
the arch. Mechanically distinct from the LVA mis-steer (which traverses fine,
then steers wrong).

### 7d. Per-dim rails — the log-std CEILING explosion (the diagnosis correction)

The user's "which dims are railing" probe was decisive. **All four dims rail
uniformly and symmetrically** (~31 % strict / ~35 % near-rail; rot dims
mean ≈ 0, no directional steering bias). The policy-network probe (healthy
update 110 k vs collapsed 1009 k) showed the **`log_std` head explodes UP to
its `+2` CEILING** on all 4 dims (mean log_std +0.01→+0.55, max pinned +2.000,
0 % at the −2 floor); pre-tanh std **1.0 → 2.0**; action *mean* stays ~0. So
the rails come from **high-variance NOISE through tanh**, and "entropy_proxy
negative" is the tanh-Jacobian penalty of large pre-squash z — a **variance
EXPLOSION misread as collapse.** `alpha` sits at 0 the whole run, but that
dormancy is a **red herring**, not the cause. Plan v11 lowered `log_std_min`
to −2 but **left `log_std_max` at the +2 default** — that untouched ceiling is
the bug.

### 7e. Seed cleared

The clean lane is **100 % LCCA-success (hook-executors), zero LVA leakage**
(1012/1012); net sampling exposure 44.7 % LCCA / 23.1 % LVA; AWAC down-weights
LVA (mean return −5.86 vs +6.16). The policy did **not** clone the seed (LCCA
15 %→7.6 %). Seed is not the cause.

## 8. EXP-1 — cap `log_std_max` (the corrected stability fix)

`log_std_max` already existed on `GaussianPolicy` (default +2) but was never
plumbed. Exposed end-to-end (committed `c7a33e3`):

| file | change |
|---|---|
| [eve_rl/eve_rl/network/gaussianpolicy.py](eve_rl/eve_rl/network/gaussianpolicy.py) | (no change — `log_std_max` param + clamp already present) |
| [training _scripts/util/agent.py](training%20_scripts/util/agent.py#L155) | `BenchAgentSynchron` gains `log_std_max` param → passed to the `GaussianPolicy(...)` call alongside `log_std_min` |
| [training _scripts/DualDeviceNav_train.py](training%20_scripts/DualDeviceNav_train.py) | new `--log_std_max` CLI (default 2.0); threaded to `BenchAgentSynchron` |

**Launcher sets `--log_std_max 0.0`** → std capped at ≤1.0. Bracketing
`log_std ∈ [-2, 0]` pins std into a healthy `[0.135, 1.0]` band on **both**
sides — structurally prevents the ceiling explosion AND a total floor
collapse.

**Why NOT `target_entropy`:** the forensic showed the bug is the ceiling, not
the dormant alpha; and holding entropy artificially high via `target_entropy`
would fight EXP-2's goal of letting the policy sharpen its mean onto the hook
demos. So `target_entropy` is left at default (dormant, now irrelevant).

## 9. EXP-2 — `balanced_fraction` 0.3 → 0.6 (up-weight the hook demos)

The clean lane is 100 % LCCA-hook demos (§7e) but only 0.3-weighted. Doubling
it to **0.6** puts far more gradient mass on the specific deflection the
policy is missing. Data-mix knob only — no reward/obs/terminal change; no seed
rebuild (the clean lane is already hook-pure, so the "filter to hook-executors"
in the plan is a no-op here).

## 10. `lcca_awac_v2` — the run (`launch_lcca_awac_v2.sh`)

Same config as v1 except EXP-1 (`--log_std_max 0.0`) + EXP-2
(`--balanced_fraction 0.6`), run name `lcca_awac_v2`.

### EXP-1 verdict — CONFIRMED WIN

Through **470 k steps**: entropy_proxy flat **2.65**, clamp_fraction **~0.5 %**,
q1_mean bounded (~−3), 0 NaN. Side-by-side, v1 at the same point had entropy
**negative** and clamp **~25 %**. **The ceiling-explosion collapse mechanism
is gone**, exactly as the corrected diagnosis predicted.

### EXP-2 verdict — UNPROVEN (run died early)

- Training-rollout tally (4,315 episodes): **LVA still 38.7 %** (unchanged),
  trunk 41.5 %, LCCA-success 8.9 %. Split into time-thirds, LCCA-success
  **rises 7.2 → 8.1 → 11.4 %** — a real ~5-σ trend v1 never showed (v1 was
  flat). Entropy stayed pinned at 2.65 (std at the cap; the policy did **not**
  sharpen).
- **Only ONE deterministic eval fired: Quality 3.06 % @257 k**, then a **host
  interruption killed the container at 470 k** (exit 255, clean kill — not a
  crash) **before eval #2.**
- **Key caveat (the v1/v2 lesson):** the deterministic eval (3 %) sat *below*
  the stochastic training success (~7–9 %) — i.e. exploration *noise* is doing
  the LCCA-hitting while the policy *mean* (what eval uses, and what deploys)
  lags. The rising 11.4 % is a **stochastic-rollout** number, **not** an eval.
  Whether the deterministic eval follows it is exactly what the (killed) full
  run would have shown.

## 11. Decision tree — what's solved, what's open

### Solved
- **Stability (EXP-1).** The `log_std_max=0` cap eliminates the ceiling
  explosion; entropy/clamp stable to 470 k. This is the durable replacement
  for the earlier (misdiagnosed) `target_entropy` idea.

### Open — the LVA structural defect
- **The relaunch of `lcca_awac_v2` (full run, same 250 k eval interval)** is
  the immediate next step — to get several deterministic evals and see whether
  eval Quality climbs past ~7 % (does the mean learn the hook?) and LVA drops
  below ~38 %. See [HANDOFF_LCCA_V2_RELAUNCH.md](HANDOFF_LCCA_V2_RELAUNCH.md)
  for running it on another machine.
- **If EXP-1+2 plateau (eval ~3–7 %, LVA ~38 %): EXP-3.** The structural fix
  lives at the bif2 decision point — a **fork-disambiguating observation
  feature** (expose the LCCA-vs-LVA ostium direction the geometry makes
  unambiguous) and/or an **LCCA-ostium waypoint reward** (reward the low-tip-x
  deflection). **EXP-3 touches observation/reward → requires explicit user
  approval** (standing rule). The cheapest confirmation that EXP-3 is needed:
  the min-tip-x-in-fork histogram (success ~50, LVA ~70); if it stays ~6 %
  <60 after EXP-1, LVA is confirmed structural.

### Out of scope under the standing rule
- Reward shaping, observation augmentation, terminal changes (EXP-3 escalation
  only, with approval), `OFF_BRANCH_GRACE_STEPS` relaxation, speed/saturation
  reward penalties.
